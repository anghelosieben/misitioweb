Introducción a la POO

La Programación Orientada a Objetos (POO) es un paradigma que organiza el software como una colección de objetos que contienen datos y comportamiento.

O
Objetos

Entidades con estado y comportamiento

C
Clases

Plantillas para crear objetos

M
Mensajes

Comunicación entre objetos

H
Herencia

Relación entre clases

Los 4 Pilares de la POO

Encapsulamiento: Ocultar detalles internos

Herencia: Reutilizar código entre clases

Polimorfismo: Un interfaz, múltiples formas

Abstracción: Simplificar la complejidad

¿Por qué usar POO?

ventajas.txt 
✓ Reutilización de código
✓ Mantenibilidad del software
✓ Modelo natural del mundo real
✓ Facilita el trabajo en equipo
✓ Modularidad y organización
✓ Fácil de depurar y extender

Clases y Objetos

Una clase es un plano o molde para crear objetos. Un objeto es una instancia de una clase.

Fundamento

Clase Básica

Estructura de una clase con propiedades y métodos.

Persona.ts 
class Persona {
  // Propiedades (atributos)
  nombre: string;
  edad: number;
  
  // Constructor
  constructor(nombre: string, edad: number) {
    this.nombre = nombre;
    this.edad = edad;
  }
  
  // Método
  saludar(): string {
    return `Hola, soy ${this.nombre}`;
  }
}
Fundamento

Crear Objetos

Instanciar una clase para crear objetos.

main.ts 
// Crear instancias de la clase Persona
const persona1 = new Persona("Ana", 25);
const persona2 = new Persona("Carlos", 30);

console.log(persona1.saludar()); // "Hola, soy Ana"
console.log(persona2.saludar()); // "Hola, soy Carlos"
Fundamento

Constructor Parametrizado

Uso de modificadores de acceso en el constructor.

Auto.ts 
class Auto {
  // Parámetros públicos en el constructor
  constructor(
    public marca: string,
    public modelo: string,
    private kilometros: number = 0
  ) {}

  conducir(km: number): void {
    this.kilometros += km;
  }

  getKilometros(): number {
    return this.kilometros;
  }
}

const miAuto = new Auto("Toyota", "Corolla");
miAuto.conducir(100);
Fundamento

Properties (Getters/Setters)

Controlar el acceso a las propiedades.

Cuenta.ts 
class CuentaBancaria {
  private _saldo: number = 0;

  get saldo(): number {
    return this._saldo;
  }

  set saldo(valor: number) {
    if (valor < 0) {
      throw new Error("No puede ser negativo");
    }
    this._saldo = valor;
  }

  depositar(monto: number): void {
    this.saldo += monto;
  }
}

Encapsulamiento

El encapsulamiento restringe el acceso directo a los datos de un objeto y solo permite修改 a través de métodos definidos.

Modificadores de Acceso

Controlan la visibilidad de miembros de una clase.

modificadores.ts 
class Ejemplo {
  public publica: string;    // Accesible desde cualquier lugar
  protected protegida: string; // Accesible en clase y subclases
  private privada: string;   // Solo en esta clase
  readonly soloLectura: string; // No se puede modificar

  constructor() {
    this.publica = "Todos ven esto";
    this.protegida = "Subclases ven esto";
    this.privada = "Solo la clase ve esto";
    this.soloLectura = "No cambia";
  }
}

Ejemplo Práctico

Clase con datos protegidos y métodos de acceso.

Usuario.ts 
class Usuario {
  private _password: string;
  
  constructor(
    public nombre: string,
    private email: string
  ) {
    this._password = "default123";
  }

  cambiarPassword(nueva: string): boolean {
    if (nueva.length < 8) {
      return false;
    }
    this._password = nueva;
    return true;
  }

  verificarPassword(pwd: string): boolean {
    return this._password === pwd;
  }
}

Herencia

La herencia permite crear una nueva clase basada en una existente, heredando sus propiedades y métodos.

Pilar

Herencia Básica

Una clase hija hereda de una clase padre.

herencia.ts 
// Clase padre
class Animal {
  constructor(public nombre: string) {}

  hablar(): void {
    console.log("Sonido");
  }
}

// Clase hija
class Perro extends Animal {
  hablar(): void {
    console.log("Guau!");
  }
}

const perro = new Perro("Rex");
perro.hablar(); // "Guau!"
Pilar

Super y Override

Acceder a la clase padre y sobrescribir métodos.

super.ts 
class Empleado {
  constructor(
    public nombre: string,
    protected salario: number
  ) {}

  calcularBonificacion(): number {
    return this.salario * 0.1;
  }
}

class Gerente extends Empleado {
  constructor(nombre: string, salario: number, public departamento: string) {
    super(nombre, salario);
  }

  calcularBonificacion(): number {
    // Llama al método del padre y añade más
    return super.calcularBonificacion() * 2;
  }
}
Pilar

Clases Abstractas

Clases que no se pueden instanciar directamente.

abstract.ts 
abstract class Figura {
  abstract calcularArea(): number;
  
  mostrarInfo(): void {
    console.log(`Área: ${this.calcularArea()}`);
  }
}

class Rectangulo extends Figura {
  constructor(public ancho: number, public alto: number) {
    super();
  }

  calcularArea(): number {
    return this.ancho * this.alto;
  }
}

Herencia Múltiple

Una clase puede implementar múltiples interfaces.

multi.ts 
interface Volador {
  volar(): void;
}

interface Nadador {
  nadar(): void;
}

class Pato implements Volador, Nadador {
  volar(): void { console.log("Volando"); }
  nadar(): void { console.log("Nadando"); }
}

Polimorfismo

El polimorfismo permite que objetos de diferentes clases respondan al mismo mensaje de maneras diferentes.

Pilar

Polimorfismo con Herencia

Mismo método, diferentes implementaciones.

polimorfismo.ts 
class Forma {
  abstract dibujar(): void;
}

class Circulo extends Forma {
  dibujar(): void {
    console.log("Dibujando círculo");
  }
}

class Cuadrado extends Forma {
  dibujar(): void {
    console.log("Dibujando cuadrado");
  }
}

function renderizar(forma: Forma): void {
  forma.dibujar();
}

renderizar(new Circulo());  // "Dibujando círculo"
renderizar(new Cuadrado()); // "Dibujando cuadrado"
Pilar

Sobrecarga de Métodos

Múltiples firmas para el mismo método.

sobrecarga.ts 
class Calculadora {
  // Sobrecarga de métodos
  sumar(a: number, b: number): number;
  sumar(a: string, b: string): string;
  sumar(a: any, b: any): any {
    return a + b;
  }
}

const calc = new Calculadora();
calc.sumar(1, 2);           // 3
calc.sumar("Hola", " Mundo");   // "Hola Mundo"
Pilar

Casting de Tipos

Convertir entre tipos de forma segura.

casting.ts 
class Gato {
  maullar(): void { console.log("Miau"); }
}

class Perro {
  ladrar(): void { console.log("Guau"); }
}

const animal: Gato | Perro = new Gato();

// Type guard
if (animal instanceof Gato) {
  animal.maullar();
}

Abstracción

La abstracción oculta los detalles complejos y solo muestra lo esencial, simplificando la interacción con los objetos.

Pilar

Clase Abstracta

Define un contrato sin implementación completa.

vehiculo.ts 
abstract class Vehiculo {
  constructor(public marca: string) {}

  abstract encender(): void;
  
  obtenerInfo(): string {
    return `Vehículo marca: ${this.marca}`;
  }
}

Implementación Práctica

Las subclases implementan los métodos abstractos.

auto.ts 
class Auto extends Vehiculo {
  encender(): void {
    console.log("`${this.marca}: Motor encendido`");
  }
}

const miAuto = new Auto("Honda");
miAuto.encender(); // "Honda: Motor encendido"
console.log(miAuto.obtenerInfo()); // "Vehículo marca: Honda"

Interfaz como Abstracción

Las interfaces definen contratos sin implementación.

reproductor.ts 
interface Reproductor {
  reproducir(): void;
  pausar(): void;
  detener(): void;
}

class Radio implements Reproductor {
  reproducir(): void { /* lógica */ }
  pausar(): void { /* lógica */ }
  detener(): void { /* lógica */ }
}

Abstracción vs Encapsulamiento

Abstracción Encapsulamiento
Oculta qué hace un objeto Oculta cómo lo hace
Se centra en la interfaz Se centra en la implementación
Nivel de clase/interfaz Nivel de miembro/dato

Interfaces

Las interfaces definen contratos que las clases deben cumplir, estableciendo qué métodos deben implementarse.

Interface Básica

Definir la forma que debe tener una clase.

Comparable.ts 
interface Comparable {
  comparar(otro: Comparable): number;
}

class Numero implements Comparable {
  constructor(public valor: number) {}

  comparar(otro: Comparable): number {
    return this.valor - (Numero as any).prototipo.valor;
  }
}

Propiedades Opcionales

Propiedades que pueden estar o no presentes.

usuario.ts 
interface Usuario {
  id: number;
  nombre: string;
  email?: string; // opcional
  telefono?: string; // opcional
}

const usuario1: Usuario = { id: 1, nombre: "Ana" };
const usuario2: Usuario = { 
  id: 2, 
  nombre: "Carlos", 
  email: "carlos@email.com" 
};

Herencia de Interfaces

Combinar múltiples interfaces.

extender.ts 
interface Serializable {
  serializar(): string;
}

interface Calculable {
  calcularTotal(): number;
}

interface Pedido extends Serializable, Calculable {
  id: number;
  items: string[];
}

Interface para Callbacks

Definir la forma de funciones de callback.

eventos.ts 
interface ManejadorEvento {
  (evento: Event): void;
}

class Boton {
  private manejadores: ManejadorEvento[] = [];

  onClick(manejador: ManejadorEvento): void {
    this.manejadores.push(manejador);
  }

  click(): void {
    this.manejadores.forEach(h => h(new Event("click")));
  }
}

Principios SOLID

Los principios SOLID son guidelines para crear software orientado a objetos mantenible y extensible.

S - Single Responsibility Principle (SRP)

Una clase debe tener una sola razón para cambiar.

Bien: responsabilidad única 
// MAL: Clase con múltiples responsabilidades
class Usuario {
  nombre: string;
  
  guardar() { /* guardar en BD */ }
  enviarEmail() { /* enviar email */ }
  generarReporte() { /* generar PDF */ }
}

// BIEN: Responsabilidad única
class Usuario { nombre: string; }
class UsuarioRepositorio { guardar(u: Usuario) {} }
class EmailService { enviar(u: Usuario) {} }
class ReporteService { generar(u: Usuario) {} }

O - Open/Closed Principle (OCP)

Las clases deben estar abiertas para extensión pero cerradas para modificación.

Extensión sin modificación 
// Usar herencia y polimorfismo
abstract class Descuento {
  abstract aplicar(precio: number): number;
}

class DescuentoNavidad extends Descuento {
  aplicar(precio: number): number {
    return precio * 0.8;
  }
}

class DescuentoBlackFriday extends Descuento {
  aplicar(precio: number): number {
    return precio * 0.5;
  }
}

L - Liskov Substitution Principle (LSP)

Los objetos de una subclase deben poder sustituir a los de la clase padre sin afectar la corrección del programa.

Sustitución correcta 
interface Ave {
  volar(): void;
}

class Pinguino implements Ave {
  volar(): void {
    throw new Error("Los pingüinos no vuelan");
  }
}

// Mejor: Separar en interfaces
interface Volador { volar(): void; }
interface Nadador { nadar(): void; }

I - Interface Segregation Principle (ISP)

Es mejor tener muchas interfaces específicas que una interfaz general.

Interfaces pequeñas y específicas 
// MAL: Interfaz grande
interface MaqFull {
  imprimir(): void;
  escanear(): void;
  fax(): void;
}

// BIEN: Interfaces separadas
interface Impresora { imprimir(): void; }
interface Escaner { escanear(): void; }
interface Fax { fax(): void; }

D - Dependency Inversion Principle (DIP)

Depender de abstracciones, no de concreciones. Las clases de alto nivel no deben depender de clases de bajo nivel.

Inyección de dependencias 
// Abstracción
interface Notificador {
  enviar(mensaje: string): void;
}

// Implementación
class NotificadorEmail implements Notificador {
  enviar(mensaje: string): void { /* email */ }
}

// Clase de alto nivel depende de abstracción
class OrdenService {
  constructor(private notificador: Notificador) {}

  crearOrden() {
    this.notificador.enviar("Orden creada");
  }
}
