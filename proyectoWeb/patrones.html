Introducción

Los patrones de diseño son soluciones probadas a problemas comunes en el diseño de software. Son plantillas que se pueden aplicar a situaciones específicas.

C
Creacionales

Controlan la creación de objetos

E
Estructurales

Relacionan clases y objetos

B
Conductuales

Definen comunicación entre objetos

Beneficios de usar Patrones

beneficios.txt 
✓ Soluciones probadas y testeadas
✓ Comunicación estandarizada entre desarrolladores
✓ Código más mantenible y extensible
✓ Facilita el diseño y la arquitectura
✓ Reutilización de buenas prácticas

Patrones Creacionales

Se ocupan de la creación de objetos, intentando crear objetos de forma adecuada a la situación.

Creacional

Singleton

Asegura que una clase tenga solo una instancia y proporciona un punto全局 de acceso a ella.

Singleton.ts 
class Configuracion {
  private static instancia: Configuracion;
  private version = "1.0.0";

  private constructor() {}

  static getInstance(): Configuracion {
    if (!Configuracion.instancia) {
      Configuracion.instancia = new Configuracion();
    }
    return Configuracion.instancia;
  }

  getVersion(): string {
    return this.version;
  }
}

const config1 = Configuracion.getInstance();
const config2 = Configuracion.getInstance();
console.log(config1 === config2); // true
Creacional

Factory Method

Define una interfaz para crear objetos pero deja que las subclases decidan qué clase instanciar.

Factory.ts 
interface Notificador {
  notificar(mensaje: string): void;
}

class NotificadorEmail implements Notificador {
  notificar(mensaje: string): void {
    console.log("Email: " + mensaje);
  }
}

class NotificadorSMS implements Notificador {
  notificar(mensaje: string): void {
    console.log("SMS: " + mensaje);
  }
}

abstract class FabricaNotificador {
  abstract crearNotificador(): Notificador;
}

class FabricaEmail extends FabricaNotificador {
  crearNotificador(): Notificador {
    return new NotificadorEmail();
  }
}
Creacional

Abstract Factory

Proporciona una interfaz para crear familias de objetos relacionados sin especificar sus clases concretas.

AbstractFactory.ts 
// Productos abstractos
interface Boton { render(): void; }
interface Input { render(): void; }

// Productos concretos - Tema Oscuro
class BotonOscuro implements Boton {
  render() { console.log("Botón oscuro"); }
}
class InputOscuro implements Input {
  render() { console.log("Input oscuro"); }
}

// Productos concretos - Tema Claro
class BotonClaro implements Boton {
  render() { console.log("Botón claro"); }
}

// Fábrica abstracta
interface FabricaUI {
  crearBoton(): Boton;
  crearInput(): Input;
}

class FabricaTemaOscuro implements FabricaUI {
  crearBoton(): Boton { return new BotonOscuro(); }
  crearInput(): Input { return new InputOscuro(); }
}
Creacional

Builder

Separa la construcción de un objeto complejo de su representación, permitiendo crear diferentes tipos.

Builder.ts 
class Pizza {
  public masa: string = "";
  public salsa: string = "";
  public queso: string = "";
  public toppings: string[] = [];
}

class PizzaBuilder {
  private pizza: Pizza;

  constructor() {
    this.pizza = new Pizza();
  }

  setMasa(tipo: string): PizzaBuilder {
    this.pizza.masa = tipo;
    return this;
  }

  setSalsa(tipo: string): PizzaBuilder {
    this.pizza.salsa = tipo;
    return this;
  }

  build(): Pizza {
    return this.pizza;
  }
}

const pizza = new PizzaBuilder()
  .setMasa("delgada")
  .setSalsa("tomate")
  .build();
Creacional

Prototype

Crea nuevos objetos copiando un prototipo existente (clonación), sin acoplar a las clases concretas.

Prototype.ts 
interface Prototipo<T> {
  clonar(): T;
}

class Usuario implements Prototipo<Usuario> {
  constructor(
    public nombre: string,
    public permisos: string[]
  ) {}

  clonar(): Usuario {
    return new Usuario(this.nombre, [...this.permisos]);
  }
}

const usuario1 = new Usuario("Ana", ["read"]);
const usuario2 = usuario1.clonar();
usuario2.nombre = "Carlos";

console.log(usuario1.nombre); // "Ana"
console.log(usuario2.nombre); // "Carlos"

Patrones Estructurales

Se ocupan de cómo las clases y objetos se combinan para formar estructuras más grandes.

Estructural

Adapter

Convierte la interfaz de una clase en otra interfaz que el cliente espera. Permite que clases incompatibles trabajen juntas.

Adapter.ts 
// Clase existente con interfaz incompatible
class ServicioPagoAnterior {
  pagarDolares(cantidad: number): void {
    console.log("Pagando $" + cantidad);
  }
}

// Interfaz esperada por el código nuevo
interface Pago {
  pagar(cantidad: number, moneda: string): void;
}

// Adapter para hacer compatible el servicio
class AdapterPago implements Pago {
  constructor(private servicio: ServicioPagoAnterior) {}

  pagar(cantidad: number, moneda: string): void {
    if (moneda === "USD") {
      this.servicio.pagarDolares(cantidad);
    } else {
      console.log("Moneda no soportada");
    }
  }
}
Estructural

Decorator

Adjunta responsabilidades adicionales a un objeto dinámicamente. Alternativa flexible a heredar para extender funcionalidad.

Decorator.ts 
// Componente base
interface Cafe {
  getDescripcion(): string;
  getCosto(): number;
}

class CafeSimple implements Cafe {
  getDescripcion() { return "Café"; }
  getCosto() { return 10; }
}

// Decorator base
abstract class DecoradorCafe implements Cafe {
  constructor(protected cafe: Cafe) {}
  getDescripcion() { return this.cafe.getDescripcion(); }
  getCosto() { return this.cafe.getCosto(); }
}

class LecheDecorator extends DecoradorCafe {
  getDescripcion() {
    return super.getDescripcion() + " + Leche";
  }
  getCosto() { return super.getCosto() + 5; }
}

const cafe = new CafeSimple();
const cafeConLeche = new LecheDecorator(cafe);
console.log(cafeConLeche.getDescripcion()); // "Café + Leche"
console.log(cafeConLeche.getCosto()); // 15
Estructural

Facade

Proporciona una interfaz unificada simplificada a un conjunto de interfaces en un subsistema. Oculta la complejidad.

Facade.ts 
// Subsistema complejo
class CPU {
  encender() { console.log("CPU encendida"); }
}
class Memoria {
  inicializar() { console.log("Memoria inicializada"); }
}
class DiscoDuro {
  cargar() { console.log("Disco cargando SO"); }
}

// Facade - interfaz simplificada
class ComputadoraFacade {
  constructor(
    private cpu: CPU,
    private memoria: Memoria,
    private disco: DiscoDuro
  ) {}

  encender(): void {
    this.disco.cargar();
    this.memoria.inicializar();
    this.cpu.encender();
  }
}

// Uso simple
const facade = new ComputadoraFacade(
  new CPU(),
  new Memoria(),
  new DiscoDuro()
);
facade.encender();
Estructural

Proxy

Proporciona un sustituto o placeholder para otro objeto, controlando el acceso al objeto original.

Proxy.ts 
interface Imagen {
  mostrar(): void;
}

class ImagenReal implements Imagen {
  constructor(private nombre: string) {}

  mostrar(): void {
    console.log("Mostrando imagen: " + this.nombre);
  }
}

class ProxyImagen implements Imagen {
  private imagenReal: ImagenReal | null = null;

  constructor(private nombre: string) {}

  mostrar(): void {
    // Carga diferida - solo crea la imagen cuando se necesita
    if (!this.imagenReal) {
      this.imagenReal = new ImagenReal(this.nombre);
    }
    this.imagenReal.mostrar();
  }
}

// La imagen real no se carga hasta que se llama mostrar()
const imagen = new ProxyImagen("foto.jpg");
console.log("Imagen creada, aún no se carga");
imagen.mostrar(); // Ahora sí se carga
Estructural

Composite

Compone objetos en estructuras de árbol para representar jerarquías parte-todo. Permite tratar objetos individuales y compuestos uniformemente.

Composite.ts 
interface Componente {
  calcularPrecio(): number;
}

class Producto implements Componente {
  constructor(public nombre: string, public precio: number) {}
  calcularPrecio() { return this.precio; }
}

class Caja implements Componente {
  private hijos: Componente[] = [];

  agregar(componente: Componente): void {
    this.hijos.push(componente);
  }

  calcularPrecio(): number {
    return this.hijos.reduce(
      (total, hijo) => total + hijo.calcularPrecio(),
      0
    );
  }
}

const caja = new Caja();
caja.agregar(new Producto("Libro", 100));
caja.agregar(new Producto("DVD", 50));
console.log(caja.calcularPrecio()); // 150

Patrones Conductuales

Se ocupan de la comunicación entre objetos, la asignación de responsabilidades y el flujo de control.

Conductual

Observer

Define una dependencia uno-a-muchos entre objetos, cuando uno cambia, todos sus dependientes son notificados automáticamente.

Observer.ts 
interface Observador {
  actualizar(estado: string): void;
}

class Sujeto {
  private observadores: Observador[] = [];

  suscribir(obs: Observador): void {
    this.observadores.push(obs);
  }

  desuscribir(obs: Observador): void {
    this.observadores = this.observadores.filter(o => o !== obs);
  }

  notificar(estado: string): void {
    this.observadores.forEach(o => o.actualizar(estado));
  }
}

class Panel implements Observador {
  actualizar(estado: string): void {
    console.log("Panel actualizado: " + estado);
  }
}

class Alerta implements Observador {
  actualizar(estado: string): void {
    console.log("Alerta: " + estado);
  }
}
Conductual

Strategy

Define una familia de algoritmos, encapsula cada uno y los hace intercambiables. Permite variar el algoritmo independientemente del cliente.

Strategy.ts 
interface EstrategiaPago {
  pagar(cantidad: number): void;
}

class PagoTarjeta implements EstrategiaPago {
  pagar(cantidad: number): void {
    console.log("Pagando " + cantidad + " con tarjeta");
  }
}

class PagoPayPal implements EstrategiaPago {
  pagar(cantidad: number): void {
    console.log("Pagando " + cantidad + " con PayPal");
  }
}

class Carrito {
  constructor(private estrategia: EstrategiaPago) {}

  setEstrategia(estrategia: EstrategiaPago): void {
    this.estrategia = estrategia;
  }

  pagar(cantidad: number): void {
    this.estrategia.pagar(cantidad);
  }
}

const carrito = new Carrito(new PagoTarjeta());
carrito.pagar(100);
carrito.setEstrategia(new PagoPayPal());
carrito.pagar(100);
Conductual

Command

Encapsula una solicitud como un objeto, permitiendo parametrizar clientes con diferentes solicitudes, encolar o deshacer operaciones.

Command.ts 
interface Comando {
  ejecutar(): void;
  deshacer(): void;
}

class Luz {
  private encendida = false;

  encender(): void {
    this.encendida = true;
    console.log("Luz encendida");
  }

  apagar(): void {
    this.encendida = false;
    console.log("Luz apagada");
  }
}

class ComandoLuzEncender implements Comando {
  constructor(private luz: Luz) {}

  ejecutar(): void { this.luz.encender(); }
  deshacer(): void { this.luz.apagar(); }
}

class Invoker {
  private historial: Comando[] = [];

  ejecutarComando(cmd: Comando): void {
    cmd.ejecutar();
    this.historial.push(cmd);
  }

  deshacer(): void {
    const cmd = this.historial.pop();
    if (cmd) cmd.deshacer();
  }
}
Conductual

State

Permite a un objeto alterar su comportamiento cuando su estado interno cambia. El objeto parecerá cambiar su clase.

State.ts 
interface EstadoPedido {
  siguiente(pedido: Pedido): void;
  anterior(pedido: Pedido): void;
  descripcion(): string;
}

class EstadoPendiente implements EstadoPedido {
  siguiente(pedido: Pedido): void {
    pedido.setEstado(new EstadoEnviado());
  }
  anterior(pedido: Pedido): void {}
  descripcion() { return "Pendiente"; }
}

class EstadoEnviado implements EstadoPedido {
  siguiente(pedido: Pedido): void {
    pedido.setEstado(new EstadoEntregado());
  }
  anterior(pedido: Pedido): void {
    pedido.setEstado(new EstadoPendiente());
  }
  descripcion() { return "Enviado"; }
}

class EstadoEntregado implements EstadoPedido {
  siguiente(pedido: Pedido): void {}
  anterior(pedido: Pedido): void {
    pedido.setEstado(new EstadoEnviado());
  }
  descripcion() { return "Entregado"; }
}

class Pedido {
  constructor(private _estado: EstadoPedido = new EstadoPendiente()) {}

  setEstado(estado: EstadoPedido): void {
    this._estado = estado;
  }

  avanzar() { this._estado.siguiente(this); }
  retroceder() { this._estado.anterior(this); }
  getDescripcion() { return this._estado.descripcion(); }
}
Conductual

Template Method

Define el esqueleto de un algoritmo en una operación, delegando algunos pasos a subclases. Permite que las subclases redefinan ciertos pasos sin cambiar la estructura.

Template.ts 
abstract class AlgoritmoOrdenamiento {
  // Template Method
  ordenar(datos: number[]): number[] {
    const copia = [...datos];
    this.inicializar(copia);
    this.ejecutarOrdenamiento(copia);
    this.finalizar(copia);
    return copia;
  }

  inicializar(datos: number[]): void {
    console.log("Inicializando ordenamiento");
  }

  finalizar(datos: number[]): void {
    console.log("Ordenamiento completado");
  }

  abstract ejecutarOrdenamiento(datos: number[]): void;
}

class OrdenamientoBurbuja extends AlgoritmoOrdenamiento {
  ejecutarOrdenamiento(datos: number[]): void {
    console.log("Ordenando con burbuja");
    // lógica de burbuja
  }
}

class OrdenamientoRapido extends AlgoritmoOrdenamiento {
  ejecutarOrdenamiento(datos: number[]): void {
    console.log("Ordenando con quicksort");
    // lógica de quicksort
  }
}
Conductual

Iterator

Proporciona una forma de acceder secuencialmente a los elementos de un objeto agregado sin exponer su representación subyacente.

Iterator.ts 
interface Iterador<T> {
  actual(): T;
  siguiente(): T;
  tieneSiguiente(): boolean;
}

class Coleccion {
  private elementos: string[] = [];

  agregar(elem: string): void {
    this.elementos.push(elem);
  }

  crearIterador(): Iterador<string> {
    return new IteradorColeccion(this.elementos);
  }
}

class IteradorColeccion implements Iterador<string> {
  private posicion = 0;

  constructor(private elementos: string[]) {}

  actual(): T { return this.elementos[this.posicion]; }
  siguiente(): T { return this.elementos[this.posicion++]; }
  tieneSiguiente(): boolean { return this.posicion < this.elementos.length; }
}

const coleccion = new Coleccion();
coleccion.agregar("A");
coleccion.agregar("B");
coleccion.agregar("C");

const iterador = coleccion.crearIterador();
while (iterador.tieneSiguiente()) {
  console.log(iterador.siguiente());
}
Conductual

Mediator

Define un objeto que encapsula cómo interactúan un conjunto de objetos. Reduce el acoplamiento evitando que los objetos se refieran explícitamente.

Mediator.ts 
interface Mediador {
  notificar(emisor: string, evento: string): void;
}

class ChatRoom implements Mediador {
  notificar(emisor: string, evento: string): void {
    console.log(`[${emisor}]: ${evento}`);
  }
}

class Usuario {
  constructor(public nombre: string, private mediador: Mediador) {}

  enviar(mensaje: string): void {
    this.mediador.notificar(this.nombre, mensaje);
  }
}

const chat = new ChatRoom();
const ana = new Usuario("Ana", chat);
const juan = new Usuario("Juan", chat);

ana.enviar("Hola Juan!");
juan.enviar("Hola Ana!");

Resumen

Categoría Patrón Propósito
Creacionales Singleton Una sola instancia全局
Factory Method Crear objetos mediante subclases
Abstract Factory Familias de objetos relacionados
Builder Construir objetos complejos paso a paso
Prototype Clonar objetos existentes
Estructurales Adapter Convertir interfaces incompatibles
Decorator Agregar responsabilidades dinámicamente
Facade Interfaz simplificada a un subsistema
Proxy Control de acceso a un objeto
Composite Estructuras de árbol parte-todo
Conductuales Observer Notificar cambios a dependencias
Strategy Intercambiar algoritmos en runtime
Command Encapsular solicitudes como objetos
State Alterar comportamiento según estado
Template Method Definir algoritmo con pasos editables

¿Cuándo usar cada uno?

guia.txt 
Creacionales → Cuando necesites controlar CÓMO se crean los objetos
Estructurales → Cuando necesites композиция de clases y objetos
Conductuales → Cuando necesites comunicación y responsabilidades entre objetos

Recuerda:
- No sobreutilices los patrones
- Adáptalos a tu contexto
- Prioriza código simple antes de patrones complejos
